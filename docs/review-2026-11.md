## 新增的自动校验

`evaluate_data_quality()`：拿**已平仓周期**反验成交完整性 —— 周期窗口内的净成交必须为 0。
不为 0 就说明成交被 6000 条上限截断或翻页漏了，会直接在日志和面板页脚报出来：

```
数据校验：抽查 7 个已平仓周期，最差成交缺口 13.73%
⚠ NVDAUSDT LONG 周期成交缺口 -477.9900（13.7%），大概率是历史成交被截断
```

## 未修（已知风险，附原因）

1. **内容哈希去重的边界**：若币安在同一毫秒产生两笔完全相同的成交（时间/价/量/手续费/已实现全同），
   会被合并成一笔，导致轻微少计。改成"按页内出现次数计数"会引入跨页重复的新风险，
   所以保留现状 —— 缺口自检能发现异常（>1% 报警）。
2. **6000 条历史上限**：更早的成交拿不到。已通过"只从上一轮平仓之后累加"规避，
   但**超过 7 天不动仓**的老仓位仍可能漏；他日均换手，实际风险低（`fill_backfill_days` 可调大）。
3. **部分平仓周期未实测**：历史 108 条全是 `All Closed`。若出现 `Partial Closed` 行，
   当前实现会把它当未平仓并跳过 cutoff，可能与成交反推重复计算 —— 等真出现再修。
4. **手机端可靠性**：ntfy fdroid 版靠长连接，ColorOS 必须手动加省电白名单，否则通知延迟。
   这是操作系统限制，代码层无解（见 `docs/phone-setup.md`）。
